What it does

One conversation, from need to cart

The catalog spans beauty, electronics, apparel and food. Users never leave the chat: structured product cards appear inline and stay tappable.

Multimodal input

Type, speak in Mandarin, or upload a product photo. Images become a search description and visual similarity re-orders the results.

Refine without restarting

Change only the budget, a brand or an ingredient and the previous search is reused with the new constraint.

换成 300 元以内的

References that resolve

Ordinals, names and pronouns map back to the products just shown, with clarification when a reference is genuinely ambiguous.

第二个有没有大瓶装？

Side-by-side comparison

Compare two or three products on the attributes that matter for their category.

Grounded product Q&A

Answers come from the product's own descriptions, official FAQs and reviews, including negative ones.

Cart and preferences

Add, remove, change quantity or variant by chat. Long-term preferences are saved with one-tap undo.

Agent design

Router, tool, composer

Instead of letting the model call tools freely, every turn runs a fixed three-stage pipeline. The model decides what to do and how to say it. Deterministic code does the work in between.

1 · Router

Pick one tool

An LLM classifies intent and rewrites the query using session context such as the last results and the product in focus.

2 · Tool

Execute deterministically

Search, comparison and cart mutations run as code and return a structured result. No generated text touches the cart.

recommendrefinecompareproduct_detailcartclarifyfallback
3 · Composer

Write the answer

The LLM writes the reply around the tool result. Product IDs must come from the payload and prices are never written by the model.

Recommendation is the dominant shopping intent, so it needs a strict search, rerank and compose path with streaming progress. Free-form tool calling would add an extra model call and make that path harder to control.

Retrieval

Hybrid RAG that respects “without”

Shoppers often say what they don't want. CartPilot treats exclusions as hard constraints at the product level, not as words that happen to match.

  1. Structured understandingCategory, price range, included and excluded brands, excluded ingredients and soft terms are parsed from the query.
  2. Filter firstHard constraints narrow candidates in SQLite and Chroma before any semantic ranking.
  3. Vector and lexical recallChroma searches evidence chunks from descriptions, FAQs and reviews while BM25 adds a keyword signal.
  4. Reciprocal rank fusionRRF merges both rankings, then an optional reranker reorders the evidence.
  5. Negative-constraint guardProducts whose evidence shows an excluded brand, category or ingredient are removed.
  6. Product aggregationChunks roll up to products, each keeping the evidence that explains why it was recommended.

Streaming

Cards first, words second

The iOS client parses a typed Server-Sent Events stream. Product cards render as soon as the tool finishes, before the model has written a word.

  1. sessionPersist the session ID
  2. statusRouting, searching, writing
  3. metaRoute and trace data
  4. tool_resultRender cards immediately
  5. tokenStream the reply text
  6. memory_updateSaved preference, undoable
  7. doneFinal narrative and timings
Engineering decisions

Trust the database, not the model

SQLite is the source of truth

Prices, SKUs, stock and cart totals are always read from SQLite. Chroma only stores semantic evidence, aligned to facts by product ID and source index.

Images become text queries

An uploaded photo is turned into a search description and sent through the proven text pipeline. Image embeddings then adjust the order.

Cautious long-term memory

Preference extraction is deterministic. Temporary wishes, questions and health statements are ignored so nothing wrong becomes a lasting preference.

A warm retriever, always

Index and model load once at startup. Cold start is about 64 s; a warm query takes about 0.01 s. Nothing is rebuilt during a request.

Every layer degrades instead of breaking

  • Router fails→fall back to recommend
  • Tool fails→safe reply plus a diagnostic trace
  • Composer fails→local narrative, cards still shown
  • No reranker→vector or hybrid order
  • Image not understood→clear message, never a guessed match
  • Any cart action→price and stock re-read from SQLite
