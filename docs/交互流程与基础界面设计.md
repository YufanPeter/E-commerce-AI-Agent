# 产品交互流程与基础界面设计文档

## 1. 文档目标

本文档面向客户端、后端、产品和 Demo 演示人员，用于在正式开发前统一“基于 RAG 的多模态电商智能导购 AI Agent”的核心交互流程、基础界面、异常状态和验收标准。

本阶段目标不是做完整电商 App，而是围绕课题要求跑通一个可信、可演示、可扩展的导购闭环：

- 用户可以通过原生 App 输入购物需求。
- Agent 能理解模糊需求、条件筛选、多轮补充、商品对比和排除约束。
- 后端通过 RAG 检索库内商品，返回流式回答和结构化商品卡片。
- 客户端在对话流中展示推荐理由、商品卡片、对比信息和异常提示。
- 整体体验接近“智能导购”，而不是传统商品列表搜索。

## 2. 设计原则

### 2.1 先闭环，后增强

Phase 1 只要求最小可用闭环：文本输入、流式回复、商品推荐卡片、商品详情跳转。不要在首期引入过多复杂页面和动效，避免影响端到端可演示性。

### 2.2 推荐必须有依据

Agent 的推荐理由需要来自数据集中的商品标题、类目、SKU、营销描述、官方 FAQ、用户评价。客户端需要在界面上通过“依据标签”“来自商品资料/FAQ/评价”等提示降低用户对 AI 编造信息的误解。

### 2.3 对话是主入口

产品不以传统搜索框和商品瀑布流为主，而以对话导购页作为主入口。用户可以像问导购一样提出需求，系统再用卡片、对比表述和追问组件承接结果。

### 2.4 UI 服务 Demo 表达

界面不追求完整交易系统，而要清楚展示评审重点：RAG 检索、流式生成、商品卡片、多轮上下文、反选约束、对比决策。

## 3. 产品信息架构

### 3.1 一级页面

建议 App 采用轻量级三层结构。

一级页面包括：

- `对话导购页`：核心首页，承载文本输入、AI 流式回复、商品推荐、对比、澄清追问。
- `商品详情页`：展示单个商品的结构化信息，包括商品标题、品牌、价格、SKU、卖点、FAQ、评价摘要。
- `购物车页`：Phase 4 可选页面，首期可只保留入口和空状态，不作为 Phase 1 必须能力。

可选辅助页面包括：

- `Demo 场景页`：展示预置问题按钮，方便现场演示快速触发标准路径。
- `会话历史页`：Phase 2 以后支持，用于恢复历史导购会话。
- `设置页`：Demo 阶段非必要，可只保留调试信息入口。

### 3.2 页面职责

#### 对话导购页

核心职责：

- 接收用户文本输入。
- 展示用户消息和 AI 消息。
- 展示 AI 正在输入、检索中、生成中等状态。
- 在 AI 回复中嵌入商品卡片。
- 支持商品卡片点击进入详情页。
- 支持用户继续追问。
- 支持 Agent 主动澄清用户需求。
- 支持错误、空结果、超时等状态提示。

首期必须具备。

#### 商品详情页

核心职责：

- 展示商品主图、标题、品牌、类目、价格区间。
- 展示 SKU 规格，例如容量、颜色、尺码、口味、包装等。
- 展示推荐理由来源，包括营销描述、FAQ、评价摘要。
- 支持返回对话页继续咨询。
- 可选支持“加入购物车”按钮，但 Phase 1 可不真正完成购物车操作。

首期建议具备简版详情页，至少保证商品卡片点击后有明确落点。

#### 购物车页

核心职责：

- 展示已加入商品、规格、数量和总价。
- 支持删除、修改数量。
- 支持模拟下单确认。

Phase 1 不强依赖，Phase 4 若选择业务闭环方向再做深。

#### Demo 场景页

核心职责：

- 提供预置问题按钮，减少现场输入成本。
- 覆盖单轮推荐、条件筛选、多轮追问、商品对比、反选约束。
- 点击问题后自动填入输入框或直接发送。

如果开发时间有限，可将 Demo 场景按钮直接放在对话导购页顶部或空状态中，不单独做页面。

## 4. 核心用户流程

### 4.1 用户首次进入 App

目标：让用户理解这是一个“可以对话的电商导购”，并快速开始提问。

流程：

1. 用户打开 App。
2. 进入对话导购页。
3. 顶部展示产品名称，例如“AI 电商导购助手”。
4. 首屏展示一句欢迎语：“告诉我你的预算、用途或偏好，我会从商品库里帮你推荐。”
5. 展示 4 到 6 个示例问题按钮。
6. 用户点击示例问题或在输入框输入需求。
7. 系统发送消息，进入导购流程。

首屏推荐问题：

- “推荐一款适合油皮的洗面奶”
- “200 元以内的蓝牙耳机有哪些？”
- “帮我推荐跑鞋”
- “推荐防晒霜，但不要含酒精”
- “我想买一件夏天通勤穿的 T 恤”

客户端要求：

- 空状态不能只显示空白页面。
- 示例问题点击后应立即进入发送状态。
- 输入框需要常驻底部，方便用户随时追问。

后端要求：

- 示例问题与普通用户输入走同一套对话接口。
- 不为 Demo 示例单独写死回答。

### 4.2 文本提问导购流程

目标：完成从用户输入到 AI 流式回复和商品卡片展示的基础闭环。

流程：

1. 用户输入：“推荐一款适合油皮的洗面奶。”
2. 客户端展示用户消息气泡。
3. 客户端展示 AI 消息占位状态：“正在理解你的需求...”
4. 后端进行意图识别和 RAG 检索。
5. 客户端状态变更为：“正在检索商品库...”
6. 后端开始流式返回自然语言回答。
7. 客户端逐字或分段渲染 AI 文本。
8. 当后端返回商品卡片事件时，客户端在当前 AI 回复下方插入商品卡片。
9. AI 回复结束后展示后续追问建议，例如“要更便宜一点吗？”“需要敏感肌可用吗？”

关键体验要求：

- 用户发送后 300ms 内需要有可见反馈。
- AI 文本可以先出，商品卡片可以随后插入。
- 如果推荐多个商品，先给结论，再给卡片。
- 卡片应能被点击，并跳转到商品详情页。

### 4.3 单轮推荐流程

适用场景：

- 用户需求较明确，且一次检索可以得到可推荐商品。
- 例如“推荐一款适合熬夜后的抗初老精华”。

流程：

1. 用户提出需求。
2. Agent 提取类目、功效、适用人群、预算等条件。
3. 后端检索商品资料、FAQ 和用户评价。
4. Agent 输出推荐结论。
5. 客户端展示 1 到 3 个商品卡片。
6. 每个商品卡片展示核心卖点和风险提醒。

AI 回复建议结构：

- 先说明“我推荐 X，因为它更匹配你的需求”。
- 再列出 2 到 3 个推荐理由。
- 如果存在明显风险，需要主动提示，例如“敏感肌建议先做局部测试”。
- 最后给用户下一步选择：“要我帮你对比容量或价格吗？”

### 4.4 多轮追问流程

适用场景：

- 用户需求模糊，需要逐步收敛。
- 例如“帮我推荐跑鞋”后，用户补充“要轻量的”“预算 500 以内”。

流程：

1. 用户输入：“帮我推荐跑鞋。”
2. Agent 判断需求缺少关键条件。
3. Agent 主动追问：“你更看重缓震、轻量、通勤百搭还是运动训练？”
4. 客户端展示澄清追问组件，包括 3 到 4 个可点击选项。
5. 用户点击“轻量”或输入“要轻量的”。
6. Agent 更新会话上下文。
7. Agent 若仍缺预算，继续追问或给出默认推荐。
8. 用户补充“预算 500 以内”。
9. Agent 使用上下文条件进行筛选并推荐商品。

上下文展示要求：

- 用户不需要重复之前的信息。
- 客户端可在 AI 回复中用轻量标签展示已识别偏好，例如“已记录：轻量、500 元以内”。
- 如果用户说“再便宜点”，系统应理解是基于上一次推荐结果继续筛选。

后端对齐点：

- 会话需要维护当前需求槽位，例如类目、预算、偏好、排除条件。
- 每次 AI 回复需要返回当前识别到的用户偏好，供客户端可视化。

### 4.5 商品对比流程

适用场景：

- 用户在多个候选商品之间犹豫。
- 例如“A 和 B 哪个更适合敏感肌？”“这两款面霜哪个更保湿？”

流程：

1. 用户在推荐结果后输入：“这两个哪个更适合敏感肌？”
2. Agent 识别“这两个”指代上一次推荐的前两个商品。
3. 后端分别检索两个商品的描述、FAQ 和评价。
4. Agent 输出对比结论。
5. 客户端展示商品对比卡片。
6. 对比卡片下方展示“更推荐 X”的结论和原因。

对比维度建议：

- 价格
- 适用人群
- 核心卖点
- 风险提醒
- 用户评价倾向
- SKU 选择复杂度
- 推荐结论

界面要求：

- 2 个商品可用左右两列对比。
- 3 个商品可用横向滑动卡片或纵向分组。
- 移动端屏幕较窄时，优先展示“结论卡片 + 分维度折叠详情”，避免密集表格难读。

### 4.6 反选和排除条件流程

适用场景：

- 用户明确提出不要某些成分、品牌、价格、属性。
- 例如“推荐防晒霜，但不要含酒精，也不要日系品牌”。

流程：

1. 用户输入包含否定约束的需求。
2. Agent 解析正向条件和排除条件。
3. 客户端可在 AI 回复中展示“已排除：含酒精、日系品牌”。
4. 后端检索候选商品并应用排除过滤。
5. Agent 输出推荐结果。
6. 若排除后结果过少或为空，Agent 说明原因并给出替代条件建议。

界面要求：

- 排除条件应以标签形式明确展示。
- 推荐理由中不得出现与排除条件冲突的商品。
- 如果无法判断某商品是否含酒精，应标记“资料中未明确”，不能强行说“不含”。

### 4.7 商品卡片点击跳转流程

流程：

1. 用户点击对话中的商品卡片。
2. 客户端打开商品详情页。
3. 商品详情页展示商品信息和推荐依据。
4. 用户点击返回，回到原会话位置。
5. 用户可以继续追问，例如“这个有大容量吗？”。

详情页展示要求：

- 顶部展示商品主图区域。
- 首屏展示标题、品牌、类目、价格区间。
- SKU 区域展示可选规格。
- 推荐依据区域展示 2 到 3 条资料来源。
- 用户评价区域展示好评和差评摘要，避免只展示正面信息。

后端对齐点：

- 商品详情页可直接使用商品 ID 获取结构化详情。
- 对话中的商品卡片需要携带 `product_id` 和默认 `sku_id`。

### 4.8 异常流程

#### 无匹配商品

触发条件：

- 检索结果为空。
- 用户条件过窄，例如“100 元以内的 iPhone”。

客户端展示：

- AI 消息：“当前商品库没有完全匹配的商品。”
- 展示已识别条件。
- 提供放宽条件按钮，例如“提高预算”“去掉品牌限制”“换个类目”。

后端要求：

- 返回空结果原因。
- 不允许编造商品补位。

#### 网络失败

触发条件：

- 请求发送失败。
- SSE 或 WebSocket 中断。

客户端展示：

- 消息气泡下方展示失败状态：“网络异常，未完成回复。”
- 提供“重试”按钮。
- 保留用户原始输入。

重试要求：

- 重试同一条消息时需要带原 message ID，避免后端重复创建多个会话状态。

#### 模型超时

触发条件：

- 检索成功但 LLM 长时间未返回。
- 首 token 超过预期阈值。

客户端展示：

- 先显示“商品已找到，正在组织回答...”
- 超时后显示：“生成时间较长，你可以重试或先查看候选商品。”
- 若后端已返回候选商品，可先展示商品卡片。

体验目标：

- 不让用户面对长时间空白。
- 尽可能保留已检索到的结构化结果。

#### 检索为空

触发条件：

- 向量库无召回。
- 结构化过滤后无商品。

客户端展示：

- 说明没有找到库内依据。
- 引导用户修改条件。
- 不展示“猜你喜欢”式无依据推荐。

#### 用户输入过于模糊

触发条件：

- 用户只说“推荐一个”“买什么好”“手机”等。

客户端展示：

- Agent 主动澄清。
- 使用选项按钮帮助用户选择方向。

澄清问题示例：

- “你更看重价格、品牌、功效还是使用场景？”
- “预算大概是多少？”
- “是自用还是送人？”

## 5. Demo 主线设计

### 5.1 Demo 路径一：单轮模糊推荐

用户输入：

- “推荐一款适合油皮的洗面奶”

展示重点：

- Agent 能理解肤质和品类。
- 返回商品卡片。
- 推荐理由来自商品描述和用户评价。

理想输出：

- 先说明推荐结论。
- 展示 2 到 3 个商品卡片。
- 提示油皮、敏感肌、预算等后续追问方向。

验收点：

- 有流式回复。
- 有商品卡片。
- 推荐理由不编造库外商品。

### 5.2 Demo 路径二：价格条件筛选

用户输入：

- “200 元以内的蓝牙耳机有哪些？”

展示重点：

- Agent 能抽取价格上限。
- 商品卡片展示价格。
- 如果没有精确匹配，需要说明并建议放宽条件。

理想输出：

- 展示“已筛选：200 元以内、蓝牙耳机”。
- 返回符合条件的商品。
- 若商品数量不足，解释“当前库内匹配较少”。

验收点：

- 价格不能编造。
- 过滤逻辑要和卡片价格一致。

### 5.3 Demo 路径三：多轮追问收敛

用户输入序列：

- 用户：“帮我推荐跑鞋”
- Agent：“你更看重轻量、缓震、通勤还是训练？”
- 用户：“要轻量的”
- Agent：“预算大概是多少？”
- 用户：“500 以内”

展示重点：

- Agent 主动追问。
- 客户端展示偏好标签。
- 多轮上下文生效。

理想输出：

- 最终推荐符合“跑鞋、轻量、500 以内”的商品。
- 推荐理由解释为什么轻量。
- 如果没有完全匹配，说明哪一项不满足。

验收点：

- 用户无需重复“跑鞋”。
- 追问选项可以点击。
- 推荐结果与上下文一致。

### 5.4 Demo 路径四：商品对比决策

用户输入：

- “这两款面霜哪个更保湿？”

前置条件：

- 上一轮已经推荐过至少 2 款面霜或护肤品。

展示重点：

- Agent 能理解“这两款”的上下文指代。
- 对比卡片按维度展示。
- 最后给出明确推荐结论。

理想输出：

- 对比保湿成分、适用肤质、价格、用户评价。
- 如果资料不足，需要说明“当前商品资料未明确提到某项”。

验收点：

- 不用重新输入商品全名。
- 对比信息来自商品资料、FAQ、评价。
- 结论清晰，不只罗列信息。

### 5.5 Demo 路径五：反选和排除约束

用户输入：

- “推荐防晒霜，但不要含酒精，也不要日系品牌”

展示重点：

- Agent 能识别否定条件。
- 客户端展示排除条件标签。
- 如果资料无法确认，Agent 不强行保证。

理想输出：

- 展示“已排除：含酒精、日系品牌”。
- 推荐符合条件的商品。
- 若库内没有明确不含酒精的商品，说明限制并建议放宽条件。

验收点：

- 不推荐与排除条件冲突的商品。
- 不能说“绝对不含”这类无依据表达。

## 6. 基础界面设计说明

### 6.1 首页 / 对话页

布局建议：

- 顶部导航栏：产品名、会话状态、可选购物车入口。
- 中部对话区域：用户气泡、AI 气泡、商品卡片、追问组件。
- 底部输入区：文本输入框、发送按钮、可选图片/语音入口。
- 空状态区域：欢迎语、能力说明、示例问题。

首屏内容建议：

- 标题：“AI 电商导购助手”
- 副文案：“告诉我你的预算、用途或偏好，我会基于商品库帮你推荐。”
- 示例问题：按美妆、数码、服饰、食品四类覆盖。

客户端注意：

- 输入框需要跟随键盘上移。
- 对话列表需要自动滚动到最新消息。
- 用户手动上滑查看历史时，不要强制打断。

### 6.2 消息气泡

用户消息：

- 靠右展示。
- 使用主色浅底或高亮底。
- 文本以用户原文为准，不做自动改写。

AI 消息：

- 靠左展示。
- 支持流式追加文本。
- 支持在同一个回复块中嵌入商品卡片、对比卡片和追问组件。

AI 消息结构建议：

- 状态行：理解中、检索中、生成中。
- 结论段：先给推荐结论。
- 理由段：分点说明。
- 商品区域：商品卡片。
- 追问段：下一步建议。

### 6.3 流式回复状态

状态分层：

- `理解中`：用户刚发送，Agent 正在解析意图。
- `检索中`：后端正在查商品库。
- `生成中`：LLM 已开始输出。
- `已完成`：回复完成。
- `失败`：网络、模型或服务错误。

展示方式：

- 理解中：短文本加轻量加载点。
- 检索中：展示“正在检索商品库，不会编造库外商品”。
- 生成中：逐字或小段追加内容。
- 已完成：移除加载状态，展示追问建议。
- 失败：展示错误文案和重试按钮。

体验建议：

- 不建议全程只显示一个转圈 loading。
- 流式文本速度不宜过快，避免闪烁。
- 商品卡片返回后可以先展示骨架屏，再填充图片和价格。

### 6.4 商品卡片

卡片字段：

- 商品图片
- 商品标题
- 品牌
- 类目 / 子类目
- 价格或价格区间
- 关键 SKU
- 1 到 2 条推荐理由
- 风险或注意事项
- 操作按钮：“查看详情”“加入购物车”

卡片信息优先级：

1. 商品标题和价格
2. 推荐匹配点
3. 规格信息
4. 评价摘要
5. 操作按钮

多商品展示：

- 1 到 2 个商品：纵向大卡片，信息更完整。
- 3 个以上商品：横向滑动卡片，保留标题、价格、主卖点。
- 对比场景：不要直接复用普通卡片，需要使用对比卡片。

卡片交互：

- 点击整卡进入商品详情页。
- 点击“查看详情”同样进入详情页。
- “加入购物车”Phase 1 可展示 Toast：“已加入模拟购物车”，Phase 4 再做真实状态管理。

### 6.5 商品对比卡片

适用场景：

- 用户明确要求比较两个或多个商品。
- Agent 认为用户处于决策阶段。

展示结构：

- 顶部：参与对比的商品缩略图和名称。
- 中部：按维度分组展示差异。
- 底部：推荐结论。

推荐维度：

- 价格：展示最低 SKU 价格或价格区间。
- 适用人群：来自商品描述和 FAQ。
- 优点：来自商品描述或好评。
- 风险：来自差评或注意事项。
- 适合谁：面向用户需求总结。

移动端适配：

- 两商品对比可左右分栏。
- 三商品对比建议使用横向滑动。
- 长文本默认折叠，点击“展开依据”查看详情。

### 6.6 澄清追问组件

触发条件：

- 用户需求过于宽泛。
- 缺少关键槽位，例如预算、用途、肤质、尺码、偏好。
- 检索结果太多，需要收敛。

组件结构：

- 一句追问文案。
- 3 到 4 个快捷选项。
- 一个“我自己输入”入口。

示例：

- 问题：“你更看重哪一点？”
- 选项：“性价比”“保湿”“敏感肌可用”“送礼好看”

交互要求：

- 用户点击选项后直接发送为一条用户消息。
- 选项内容进入会话上下文。
- 用户也可以不点选项，直接输入自由文本。

### 6.7 推荐理由组件

目标：

- 让用户知道推荐不是拍脑袋。
- 让评审能看到 RAG 证据链。

推荐理由结构：

- `匹配需求`：说明商品为什么符合用户输入。
- `商品资料`：引用营销描述、规格、FAQ。
- `用户反馈`：引用评价中的好评或差评趋势。
- `注意事项`：提示不确定或风险点。

展示方式：

- 普通回答中用简短分点展示。
- 商品卡片内展示 1 到 2 条最关键理由。
- 详情页展示更完整依据。

文案要求：

- 避免“全网最好”“绝对适合”等夸张表达。
- 遇到资料不足时明确说“当前资料未明确提到”。
- 对功效、适用人群、价格等敏感信息必须基于库内资料。

### 6.8 错误提示组件

错误类型：

- 网络异常
- 服务超时
- 检索为空
- 模型生成失败
- 图片加载失败
- 商品详情加载失败

展示原则：

- 错误提示要出现在发生错误的位置。
- 允许用户重试。
- 不清空已生成内容。
- 不使用技术错误码作为主要文案。

文案示例：

- 网络异常：“网络连接不稳定，这次回复没有完成。”
- 模型超时：“回答生成时间较长，可以重试，或先查看已找到的商品。”
- 检索为空：“当前商品库没有找到完全匹配的结果，要不要放宽预算或减少限制？”

### 6.9 加载态 / 空状态 / 失败态

加载态：

- 对话回复使用流式状态，不只用全屏 loading。
- 商品卡片使用图片骨架、标题骨架和价格骨架。
- 详情页加载时保留返回按钮。

空状态：

- 首次进入展示欢迎语和示例问题。
- 搜索无结果展示条件摘要和放宽条件建议。
- 购物车空状态展示“你可以在对话中说：把这款加入购物车”。

失败态：

- 单条消息失败：在消息下方显示重试。
- 商品详情失败：页面内显示“重新加载”。
- 会话整体失败：保留历史消息，提示刷新或重试。

## 7. 交互细节

### 7.1 AI 回复如何边生成边展示

客户端应支持后端分事件返回：

- 文本片段事件：追加到当前 AI 气泡。
- 状态事件：更新“理解中/检索中/生成中”。
- 商品卡片事件：插入商品卡片。
- 追问建议事件：展示快捷选项。
- 完成事件：结束 loading。
- 错误事件：展示错误组件。

表现要求：

- 同一轮 AI 回复应保持在一个消息块内，不要拆成大量碎片气泡。
- 商品卡片可以出现在文本结论之后。
- 如果商品卡片先于完整文本返回，可以先展示卡片骨架。

### 7.2 商品卡片何时出现

商品卡片出现条件：

- 用户明确要求推荐商品。
- Agent 已检索到至少一个库内商品。
- 后端返回结构化商品 ID 和展示字段。

商品卡片不应出现的场景：

- Agent 只是在澄清问题。
- 检索为空。
- 用户问的是泛知识问题且无具体推荐需求。
- 商品资料不足以支持推荐。

### 7.3 多个商品如何展示

推荐场景：

- 优先展示 3 个以内商品。
- 每个商品说明适合人群，避免“列表堆砌”。

对比场景：

- 2 个商品使用对比卡片。
- 3 个商品使用横向滑动对比。
- 超过 3 个商品时，Agent 应先缩小范围或询问用户偏好。

组合推荐场景：

- 按场景分组，例如“防晒”“服饰”“饮品”。
- 每组最多展示 1 到 2 个商品。

### 7.4 用户如何继续追问

入口：

- 底部输入框常驻。
- AI 回复末尾展示追问建议。
- 商品卡片上提供快捷问题，例如“适合敏感肌吗？”“有什么差评？”“哪个规格划算？”

追问处理：

- 用户输入“这个”“刚才那款”“第二个”时，后端需要结合会话上下文解析指代。
- 客户端不强行解析指代，但应把当前会话 ID 和最近商品 ID 列表传给后端。

### 7.5 Agent 如何主动澄清

主动澄清触发：

- 类目过大：例如“推荐手机”。
- 预算缺失且候选商品价格跨度大。
- 关键偏好冲突：例如“便宜一点但要旗舰性能”。
- 排除条件导致无结果。

澄清方式：

- 一次只问一个最关键问题。
- 提供可点选项。
- 允许用户跳过，Agent 给出默认推荐并说明假设。

文案示例：

- “手机差异比较大，我先确认一个点：你更看重拍照、续航还是性价比？”
- “你提到不要含酒精，但当前资料中部分商品没有明确成分表。要不要只看资料明确的商品？”

### 7.6 如何避免用户误以为 AI 编造信息

界面策略：

- 在检索状态展示“正在检索商品库”。
- 在推荐理由旁展示“依据：商品资料 / 官方 FAQ / 用户评价”。
- 对不确定信息展示“不确定”而不是强行肯定。
- 对价格、SKU、品牌等结构化字段直接来自商品数据，不由 AI 自由生成。

文案策略：

- 使用“根据当前商品资料”“从用户评价看”“FAQ 中提到”等表达。
- 避免“官方承诺”“全网最低价”“库存充足”等数据集中没有的信息。
- 遇到用户问优惠、库存、物流时，若数据集没有字段，应提示暂不支持。

### 7.7 推荐理由如何引用商品描述、FAQ、用户评价

引用层级：

- 商品描述用于说明核心卖点、适用场景、使用建议。
- FAQ 用于回答规格选择、成分作用、保养方式、使用方式等明确问题。
- 用户评价用于补充真实体验，包括优点和风险。

客户端展示：

- 普通卡片展示简版依据。
- 详情页展示完整依据摘要。
- 对比卡片按维度展示依据。

示例表达：

- “商品资料提到它主打夜间修护和保湿。”
- “FAQ 中建议敏感肌先做局部测试。”
- “评价中有用户反馈吸收快，也有人提到敏感肌刺痛风险。”

## 8. UI 风格建议

### 8.1 视觉定位

关键词：

- 轻量
- 可信
- 温暖
- 商业产品感
- 智能但不过度炫技

整体风格建议接近现代电商 App 与 AI 对话助手结合：对话区域清爽，商品卡片具备电商转化感，推荐理由具备可信解释感。

### 8.2 色彩

主色建议：

- 使用偏温暖的橙色、珊瑚色或电商红作为行动色。
- 背景使用浅灰或暖白，降低长时间阅读压力。
- AI 气泡使用白色卡片，用户气泡使用浅主色。

功能色：

- 成功：绿色，用于加入购物车或匹配成功。
- 警示：橙色，用于注意事项和风险提醒。
- 错误：红色，用于失败和不可用状态。
- 信息：蓝色或灰蓝，用于依据标签和系统状态。

注意：

- 不建议大面积使用高饱和红色，容易让对话页显得嘈杂。
- 价格可以使用强调色，但不要抢过推荐结论。

### 8.3 字体层级

建议层级：

- 页面标题：18 到 20sp，半粗。
- 商品标题：15 到 16sp，半粗，最多两行。
- 正文回复：15 到 16sp，常规。
- 推荐理由：13 到 14sp，常规。
- 标签和辅助信息：11 到 12sp。
- 价格：16 到 18sp，半粗或粗体。

阅读原则：

- AI 回复不宜长段落堆叠。
- 推荐理由尽量分点。
- 卡片内每个区域最多展示 2 到 3 行。

### 8.4 卡片样式

普通商品卡：

- 圆角 12 到 16。
- 白底。
- 轻阴影或浅边框。
- 图片区域固定比例。
- 价格和按钮视觉突出。

对比卡：

- 边框更清晰。
- 维度分组明确。
- 结论区域用浅色底强调。

依据标签：

- 使用小号胶囊标签。
- 文案例如“商品资料”“FAQ”“用户评价”。

### 8.5 信息密度

对话页：

- 一屏内优先展示用户问题、AI 结论和首个商品卡片。
- 不要在卡片内塞入完整营销描述。

详情页：

- 可以承载更高信息密度。
- 按“基础信息、SKU、推荐依据、FAQ、评价摘要”分区。

对比页或对比卡：

- 先给结论，再给明细。
- 长文本默认折叠。

### 8.6 动效建议

必要动效：

- AI 输入中的点状 loading。
- 流式文字出现。
- 商品卡片淡入。
- 点击卡片的轻微按压态。

可选动效：

- 加入购物车飞入动画。
- 卡片横滑吸附。
- 追问选项点击后变为已选择状态。

不建议：

- 复杂 3D 动效。
- 过长开屏动画。
- 影响流式阅读的频繁闪烁。

### 8.7 商业产品感体现

关键点：

- 商品图片和价格要清晰。
- 推荐结论要像真实导购，而不是搜索结果摘要。
- 商品卡片要有明确行动按钮。
- 异常状态要完整，不要露出技术栈错误。
- FAQ 和评价摘要要体现可信度。
- Demo 路径要稳定，避免现场等待过久。

## 9. 客户端验收标准

### 9.1 Phase 1 必须具备

页面：

- 对话导购页
- 商品卡片
- 简版商品详情页

流程：

- 用户输入文本并发送。
- AI 流式回复。
- 展示至少 1 个商品卡片。
- 点击商品卡片进入详情页。
- 网络失败可重试。
- 检索为空有明确提示。

状态：

- 首次进入空状态。
- 消息发送中。
- AI 理解中。
- 商品检索中。
- AI 生成中。
- 回复完成。
- 回复失败。

交互：

- 示例问题可点击。
- 输入框常驻底部。
- 对话自动滚动。
- 商品卡片可点击。

### 9.2 Phase 2 建议具备

页面和组件：

- 澄清追问组件
- 偏好标签
- 追问建议按钮
- 会话上下文展示

流程：

- 多轮追问。
- 用户补充预算、偏好、用途。
- Agent 主动澄清。
- 用户说“再便宜点”“换一个”时能基于上轮继续。

状态：

- 需求槽位已识别。
- 需求信息不足。
- 候选商品过多。

### 9.3 Phase 3 建议具备

页面和组件：

- 商品对比卡片
- 推荐依据展开
- 排除条件标签
- 评价摘要模块

流程：

- 两个商品对比。
- 反选和排除条件。
- 场景化组合推荐。
- 商品优缺点总结。

状态：

- 排除后无结果。
- 商品资料不足。
- 对比对象缺失。

### 9.4 Phase 4 可延后

可延后能力：

- 完整购物车管理。
- 自然语言删除或修改购物车。
- 模拟下单确认。
- 语音输入。
- TTS 播报。
- 拍照找货。
- 高级动效。
- 会话历史云同步。

如果选择 Phase 4 做精方向，建议优先级：

1. 对话智能与 RAG 增强：多轮上下文、反选、多商品对比。
2. 购物车入门闭环：对话式加购和购物车状态展示。
3. 性能体验优化：首 token、骨架屏、流畅卡片动效。
4. 多模态：语音输入或拍照找货，视团队端侧能力决定。

## 11. Demo 验收脚本

### 11.1 基础闭环脚本

操作：

1. 打开 App。
2. 点击示例问题“推荐一款适合油皮的洗面奶”。
3. 观察 AI 流式回复。
4. 观察商品卡片出现。
5. 点击商品卡片进入详情页。
6. 返回对话页继续提问。

通过标准：

- 全流程无崩溃。
- 回复中出现库内商品。
- 商品详情与卡片商品一致。

### 11.2 多轮脚本

操作：

1. 输入“帮我推荐跑鞋”。
2. 点击“轻量”。
3. 输入“预算 500 以内”。
4. 查看最终推荐。

通过标准：

- Agent 主动澄清。
- 后续推荐保留上下文。
- 客户端展示已识别偏好。

### 11.3 对比脚本

操作：

1. 先让系统推荐 2 款护肤品。
2. 输入“这两个哪个更适合敏感肌？”
3. 查看对比卡片。

通过标准：

- 正确识别“这两个”。
- 对比维度清晰。
- 结论有依据。

### 11.4 反选脚本

操作：

1. 输入“推荐防晒霜，但不要含酒精，也不要日系品牌”。
2. 查看排除条件标签。
3. 查看推荐结果或无结果提示。

通过标准：

- 排除条件被明确展示。
- 不推荐明显冲突商品。
- 资料不足时不做绝对承诺。

## 12. 结论

本产品的客户端体验应围绕“对话式导购可信闭环”设计。Phase 1 优先保证对话、流式回复、商品卡片、详情跳转和异常状态完整；Phase 2 和 Phase 3 再增强多轮、澄清、对比、反选等 Agent 能力；Phase 4 可以选择购物车、多模态或体验优化，但从当前数据集和评审重点看，最值得做深的是“对话智能与 RAG 增强”。
